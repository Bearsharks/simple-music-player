# 아키텍처: 경계와 책임

## 구조

```text
앱 조립 → 기능 UI·업무 상태 → 공통 저장·UI·인프라
                 ↕
             외부 서비스

확장 UI → 확장 상태·대상 탭 → 검증된 메시지 경계 → 앱
```

- **앱 조립 계층:** 진입점, 라우터, 전역 호스트와 기능 간 배치를 연결한다. 업무 상태나 저장 구현을 복제하지 않는다.
- **기능 계층:** 사용자 작업과 해당 상태·규칙·실패 처리를 소유한다. 기능 간 계약을 변경하면 소비자까지 검증한다.
- **공통 계층:** 범용 UI, 인프라, 저장 어댑터와 값 계약을 제공한다. 기능·앱 계층으로 역의존하지 않는다.
- **확장 경계:** 브라우저 권한, 담은 항목, 대상 탭과 수신 확인을 소유한다. 앱의 목록 조회·편집·저장 책임을 대신하지 않는다.
- **외부 경계:** YouTube 응답·임베드·브라우저 메시지를 검증하고, 외부 실패를 내부 편집본·저장 상태와 분리한다.

## 상태와 의존

- 영속 상태, 작업 draft, 대기열과 재생 상태는 수명과 책임이 다르다. 표시 상태만으로 영속 성공을 추정하지 않는다.
- app이 기능을 조립하며 기능이 app 내부에 의존하지 않는다. shared는 기능 업무를 알지 않는다.
- 공용 타입이나 전역 상태가 편리하다는 이유로 모든 업무를 중앙 파일에 모으지 않는다. 작은 공개 계약과 명확한 소유권을 우선한다.
- 기존 기능 간 조정과 전역 플레이어 의존이 있으므로 완전한 모듈 독립성을 가정하지 않는다. 실제 참조·검증 경로로 경계를 확인한다.
- 하나의 탭에서의 직렬화와 다중 탭에서의 일관성은 별개다. 데이터 모델 변경은 재현·측정·복구 계약을 먼저 정한다.

## 배포 경계

소스, 검증한 정적 산출물, 운영 게시 상태를 구분한다. 게시 과정은 검증한 바이트를 전달하며 업무 데이터나 저장 스키마를 변경하지 않는다. 웹 앱과 확장은 각각의 런타임 경계를 유지하되 호환되는 계약으로 함께 검증한다.
