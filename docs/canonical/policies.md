# 현재 유효한 정책

## 데이터와 제품 동작

- 브라우저 로컬 저장을 기본으로 한다. 인증·서버 저장·기기 간 동기화를 임의로 활성화하지 않는다.
- 도메인·저장소 이름·키·스키마 변경은 데이터 이전 작업이다. 구조 정리와 섞지 않는다.
- 저장 목록, 최초 snapshot, 현재 대기열은 독립된 상태다. 한쪽의 편집·복원·조회가 다른 쪽을 암묵적으로 바꾸지 않는다.
- 영속 저장은 transaction 완료 후 성공 처리한다. 실패 시 편집본을 유지하고, 쓰기 중 중복 제출과 닫기를 차단한다.
- 사용자 입력·순서·선택·허용된 중복을 보존한다. 늦은 결과로 사용자가 편집하거나 지운 값을 덮어쓰지 않는다.
- 대기열 추가는 편집 모달을 유지하고 결과를 알린다. 가져온 목록의 편집 모달은 저장 성공 또는 명시적 닫기로 종료한다.
- 목록 펼치기는 앱이 담당한다. 공식 플레이어가 제공한 결과를 원본 전체라고 보장하지 않는다.

## 확장과 외부 입력

- 연결 상태 확인은 앱 시작과 명시적 확인에서 수행한다. 목록 수신은 확장의 저장 알림에 반응한다.
- 확장 전달 항목은 종류와 ID로 제한한다. 표시용 제목·썸네일은 권위 있는 전달 데이터로 취급하지 않는다.
- 실제 메시지 발신자, 출처, frame, 대상 탭과 스키마를 검증한다. DOM 메시지는 권한·항목·수신 확인의 근거가 아니다.
- 수신 확인된 항목만 비우고 실패·미전송·나중에 담은 항목은 보존한다. 수신 확인과 최종 저장은 구분한다.
- 운영 산출물은 운영 출처만 탐색·허용한다. 개발 주소와 권한은 개발 산출물에만 둔다.
- 외부 URL·ID·응답을 검증한다. 응답 HTML이나 원격 코드를 실행하지 않는다. 인증 오류를 무조건 재시도하지 않는다.

## 안전과 검증

- 비밀 값·토큰·개인 환경 값을 로그·커밋·artifact에 포함하지 않는다.
- 검증은 격리된 데이터와 프로필을 사용한다. 운영 API 변경이나 실제 사용자 데이터 수정으로 시험하지 않는다.
- 실패·제약·확인 범위를 숨기지 않는다. 게시·재생·수집 완료는 실제 확인한 범위로만 표현한다.
