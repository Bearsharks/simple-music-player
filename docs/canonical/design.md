# 디자인 정책

## 표현과 입력

- 필요한 작업명·라벨·오류·확인만 표시한다. 홍보 문구, 기능을 되풀이하는 설명, 장문의 상시 안내는 붙이지 않는다.
- 조작 가능 여부·선택·진행 상태는 실제 컨트롤 상태로 표현한다. 입력이 필수 조건을 충족하지 않으면 제출을 비활성화한다.
- 입력 오류는 해당 입력 바로 아래에 공통 UI로 표시하고 접근성 설명을 연결한다. 첫 진입부터 오류를 표시하지 않으며 수정 후 해제한다.
- 특정 입력으로 해결할 수 없는 작업 오류는 작업 영역에서 알리고 편집본을 유지한다.
- IME 입력·키보드 이동·사용자 선택을 보호한다. 로딩 중 편집 가능 상태와 실제 쓰기 중 잠금 상태를 구분한다.

## 공통 UI와 접근성

- 토큰과 공통 컨트롤을 재사용한다. 색·크기·상태·스타일 값을 기능별 문서에 복제하지 않는다.
- 전역 reset·Preflight로 기존 스타일 경계를 바꾸지 않는다. 외부 UI 갱신도 로컬 포커스·portal·접근성 계약을 보존해 검증한다.
- 브랜드의 대표 CTA와 일반 저장·생성·재생 조작의 시각적 역할을 구분한다.
- 터치 목표는 최소44px를 기본으로 하며 키보드 focus, 접근 가능한 이름, reduced-motion을 보장한다.
- 설명·긴 목록은 정해진 영역에서 스크롤하며, 좁은 화면에서 입력과 주요 작업에 접근할 수 있어야 한다.
- 폰트와 외부 UI의 라이선스·출처를 함께 보존한다.

## 레이어와 재생

- z-index 숫자만 올리지 않고 stacking context·native top layer·portal host를 함께 다룬다.
- 메뉴·음량·알림은 현재 작업 scope 안에서 조작할 수 있어야 한다. 모달의 포커스·inert·닫기 순서를 보존한다.
- 안쪽 메뉴를 닫는 Escape가 바깥 작업까지 연쇄 종료하지 않게 한다. 작업별 명시적 닫기 정책을 따른다.
- overlay를 열고 닫거나 화면 크기를 바꿔도 기존 재생 iframe과 편집 상태를 잃지 않는다. 본문 레이아웃을 불필요하게 밀지 않는다.
- 미리듣기 전환과 기존 재생의 관계를 명시적으로 처리하며, 사용자 의도 없이 자동 재개하지 않는다.
