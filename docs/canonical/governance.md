# 거버넌스

## 문서의 권위

- 현재 프로젝트 기준은 이 디렉터리에서 관리한다. 명시적으로 합의한 사용자 요구를 반영하고, 충돌하는 기준을 발견하면 구현 전에 정리한다.
- 구현 사실의 원본은 코드·설정·테스트다. 동작과 정책이 다르면 어느 쪽이 맞는지 확인하며, 현재 코드라는 이유만으로 정책을 덮어쓰지 않는다.
- archive는 결정과 검수의 근거다. 현재 작업 지침으로 자동 적용하지 않는다.

## 변경 승인

- 기존 데이터·보안·사용자 동작을 보존하는 범위에서 변경한다. 범위를 넓히는 데이터 이전·인증 도입·백엔드 교체는 먼저 합의한다.
- 운영 배포, 계정·권한·DNS 변경, 파괴적 작업과 force push는 명시적 승인 없이 수행하지 않는다.
- 검증한 최신 제품 코드는 main에 통합한다. 진행 중인 브랜치만을 제품의 유일한 소스로 남기지 않는다.
- 의존성 갱신과 구조 변경은 분리해 검증한다.

## 문서 유지

- canonical에는 코드만으로 알 수 없는 원칙·정책·책임·작업 기준을 쓴다.
- 구현 순서, 함수·파일 목록, 설정 값, 테스트 수와 현재 버전은 코드나 자동 산출물에 링크한다.
- 같은 정책은 한 곳에서 관리한다. 진입 문서와 기능 README는 인덱스로 유지한다.
- 결정 사유, 대안, 작업 이력, 검수 결과는 날짜별 archive에 소스 SHA와 함께 기록한다. 비밀 값과 개인 환경 값은 기록하지 않는다.
- 정책 변경 시 해당 canonical 문서를 갱신하고 링크를 확인한다. 원본·라이선스·출처 보관 자료는 유지한다.
