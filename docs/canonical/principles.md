# 원칙

- **단순한 흐름:** 작업에 필요한 시점에 반응한다. 반복 확인·중복 상태·별도 프레임워크를 기본 해법으로 삼지 않는다.
- **명확한 소유권:** 데이터와 업무 규칙은 책임 계층에서 관리한다. 화면이나 공통 UI에 저장·전송 로직을 복제하지 않는다.
- **데이터 우선:** 실패·취소·늦은 응답이 편집본이나 저장 데이터를 잃게 하지 않는다.
- **명시적 변경:** 미리보기·선택·가져오기와 영속 저장을 구분한다. 파괴적인 교체에는 명시적 의도를 요구한다.
- **사실만 표시:** 확인한 결과만 성공·완료로 표현한다. 일부 결과를 원본 전체라고 부르지 않는다.
- **최소 문구:** 설명을 늘리기보다 조작과 상태로 동작을 드러낸다. 오류·확인·접근성·실제 제한은 필요한 만큼 명확히 알린다.
- **측정 후 확장:** 성능·다중 탭·결합 문제를 재현하고 작은 경계부터 개선한다. 추측만으로 스키마나 엔진을 교체하지 않는다.
- **재현 가능한 전달:** 승인한 소스와 검증한 산출물이 운영에 그대로 도달했음을 확인한다.
