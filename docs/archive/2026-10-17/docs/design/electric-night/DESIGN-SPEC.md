# SMP Electric Night · 확정 디자인 인수 명세

2026-10-16 · Astra design decision · Prototype v1.0

## 1. 결정

Electric Night를 채택한다. SMP 이름은 유지한다. Primary는 #A855FF, 배경은 #0B0B14, 표면은 #1A1A26이다. Purple → Pink → Blue의 시그니처 그라디언트는 재생 버튼과 목록 식별 커버에 집중한다. 일반 메뉴와 음악 정보는 무채색으로 읽히게 한다.

이 제품의 중심은 **내 음악을 찾고 → 재생하면서 → 목록과 큐를 독립적으로 다루는 경험**이다. 채워진 라이브러리의 홍보용 대형 히어로는 제거했다. 최초 빈 상태에서만 파형·Feel Every Beat ↗·짧은 사용 안내를 보여준다. 모든 화면에 네온과 유광 효과를 뿌리지 않는다.

**인수 대상은 아래 화면/상태/상호작용 계약이다. 프로토타입의 임시 저장/모의 재생 코드를 실제 앱에 이식하는 것이 아니다.** 실제 앱은 IndexedDB, 기존 YouTube URL 검증과 공식 임베드, 로컬 편집, CSP를 보존한다. 로그인·서버·실제 데이터 조회 기능을 새로 추가하지 않는다.

## 2. 파일과 실행

앱 소스를 수정하지 않은 독립 정적 프로토타입이다. 네트워크 라이브러리·웹폰트·CDN·외부 이미지에 의존하지 않는다.

- `index.html`: 앱 shell, native dialog, 알림 영역
- `tokens.css`: 확정 컬러/간격/레이아웃 토큰
- `prototype.css`: desktop/mobile 화면과 상태 스타일
- `prototype.js`: 예시 데이터, UI 상태, 상호작용
- `DESIGN-SPEC.md`: 이 명세
- `ACCEPTANCE.md`: 독립 검수 시나리오
- `verify-prototype.mjs`: jsdom 기반 동작 검증
- `VERIFICATION.json`: 실행한 검증 결과
- `capture-prototype.mjs`: Chromium 캡처용 도구. 실제 실행 결과는 별도 확인

런타임과 검증 스크립트는 `prototype/` 하위 폴더에 있다. 4개 런타임 파일을 같은 폴더에 두고 `index.html`을 열면 된다. 검수에는 정적 HTTP 서버를 권장한다:

```sh
python3 -m http.server 4180 --directory docs/design/electric-night/prototype
```

- 기본: `/index.html?fresh=1`
- 빈 상태: `?fresh=1&scene=empty`
- 상세: `?fresh=1&scene=detail`
- 지금 재생: `?fresh=1&scene=playing`
- 큐: `?fresh=1&scene=queue`
- 재생 오류: `?fresh=1&scene=error`
- 읽기 오류: `?fresh=1&scene=read-error`
- 가져오기: `?fresh=1&scene=import`

상단 ‘프로토타입 / 시연 설정’에서 상태를 직접 바꿀 수도 있다. `fresh=1`은 화면 시작 시 예시 데이터를 사용한다. 그 뒤 실제로 저장하는 데모 동작은 독립 데모 저장소에 남는다. 시연 화면 전환 자체는 저장소를 즉시 덮어쓰지 않지만, 전환한 데이터에서 다음 저장을 실행하면 그 현재 데모 데이터가 저장된다. 이 동작은 제품 기능이 아니라 검수 도구다.

### 실제 앱과의 경계

- 데모 저장 키: `smp-electric-night-prototype-v1` (`localStorage`). 실제 앱의 IndexedDB에 접근하지 않는다.
- 예시 곡/시간/커버는 디자인 시연 데이터다. 사용자 음악/실제 메타데이터를 의미하지 않는다.
- 가져오기 미리보기는 외부 접속 없이 예시 6곡을 만든다. 실제 YouTube 성공을 주장하지 않는다.
- 재생은 시계와 상태의 시연이다. 소리, 영상 iframe, 오디오 분석기는 구현하지 않았다.
- 실제 앱에서는 시연 배지·시연 설정·예시 데이터·가짜 길이를 제거한다. 데이터가 없으면 빈 상태, 모르는 길이는 ‘—’로 표시한다.

## 3. 확정 토큰과 스타일 규칙

실제 값은 `tokens.css`가 기준이다.

| 역할 | 값 |
|---|---|
| Canvas | #0B0B14 |
| Surface | #1A1A26 |
| Raised surface | #242435 |
| 장식 구분선 | #353545 |
| 입력 경계 | #6B6B80 |
| Primary text | #FFFFFF |
| Secondary text | #A1A1B3 |
| Primary / 선택 / 진행률 | #A855FF |
| 플레이어 보조 강조 | #FF4D8D |
| 파형 하이라이트 / focus | #4CC9FF |
| 색 면의 텍스트·아이콘 | #0B0B14 |
| 선택 배경 | rgba(168,85,255,0.12) |
| 시그니처 | 120deg, Purple 0% → Pink 58% → Sky 100% |

- 어두운 기능 면이 전체 인상을 지배한다. Dark 70 / Surface 20 / Violet 8 / Pink·Blue 2는 방향이지 정확한 픽셀 할당이 아니다. 실제 썸네일 색을 억지로 수정하지 않는다.
- Purple/Pink 위의 작은 흰 글자는 대비가 부족하다. 주색 버튼에는 어두운 글자/아이콘을 쓴다. 대비는 단색뿐 아니라 그라디언트 중간 구간에서도 검증한다.
- destructive는 아이콘·명확한 문구·확인/복구로 구별한다. 브랜드 핑크와 색만으로 의미를 나누지 않는다.
- 글꼴은 시스템/Korean sans 우선. 이번 인수에 별도 유료·외부 폰트가 필요하지 않다.
- 간격: 4/8/12/16/24/32px. 모서리: 조작 10, 커버 12, dialog/sheet 16px. 원형 재생 버튼은 예외.
- 앱 제목 28px, 상세 제목 32px(모바일 26px), 곡/카드 제목 14–16px, 일반 본문 14px, 보조 12–14px, 입력 16px.
- 한국어 본문 줄높이 1.5–1.6. 과도한 음수 자간·7–9px 장식 라벨을 쓰지 않는다.
- 핵심 터치 표적 44px. 키보드 포커스는 2px Sky + 충분한 offset. reduced-motion에서는 transition/animation 제거.

### 커버

사용자 참고 이미지의 파형 감각을 독립적인 코드 그래픽으로 옮겼다. 전체 브랜드 보드나 기기 목업을 화면 배경으로 복사하지 않는다. 목록 ID에 고정된 seed가 색·파형을 정한다. 검색/정렬/이름 변경에도 커버는 유지된다. 라이브러리/사이드바/상세에서 같은 커버를 사용한다. 실제 썸네일이 있으면 그것을 사용하고 없음/실패 시 같은 fallback으로 돌아간다.

## 4. 레이아웃

### Desktop ≥1200px

- Rail 208px, dock 88px, 선택적 우측 큐 320px.
- 큐가 없을 때 초기 패널은 접힘. 사용자 첫 재생에서는 플레이어 접근을 보여주기 위해 열 수 있다. 이후 사용자가 접으면 다음 곡/편집에서 강제로 다시 열지 않는다.
- 열려 있는 큐는 비모달이다. 중앙 저장 목록을 편집하면서 우측 큐의 곡/순서를 편집할 수 있다. 사용자의 열림 상태를 보존한다.
- 고정 dock에서 현재곡 영역은 지금 재생으로, 큐 버튼은 재생 대기열로 진입한다. 실제 보임과 `aria-expanded`를 일치시킨다.
- 상단은 64px, 본문 padding 24–32px. 라이브러리 제목·수·생성/가져오기 → 검색/정렬 → 카드.
- 커버 크기는 공간에 맞춰 약 174–220px. 눈에 보이는 정보량을 유지하며 과도하게 큰 빈 커버를 만들지 않는다.

### Tablet 761–1199px

- Rail 유지, 우측 패널은 380px modal drawer. 뒤 콘텐츠는 inert, scrim으로 관계를 명확하게 한다.
- 닫으면 원래 버튼으로 포커스가 복귀한다. 화면 폭을 넘지 않고 내용만 스크롤한다.

### Mobile ≤760px

- Rail 숨김. 상단 56px. 본문 padding 16px. 라이브러리 2열/gap 16px.
- 제목 옆 가져오기/생성은 명확한 접근성 이름이 있는 44px 버튼으로 축약한다.
- 첫 커버 y≤240, 390×844에서 첫 4개 카드 제목이 dock 위에 보여야 한다.
- Dock는 72px + safe area. 현재곡 텍스트/재생/큐 진입이 우선이다. 이전/다음·음량은 확장 플레이어에 있다.
- **모바일 dock의 얇은 진행선은 읽기 전용이다.** 작은 표적에 seek를 숨기지 않는다. 현재곡을 눌러 확장 플레이어에서 44px 높이의 seek 영역을 사용한다.
- 확장 플레이어/큐는 전체 높이의 modal sheet이며 ‘지금 재생 / 재생 대기열’ 탭을 제공한다. 닫기·Escape·포커스 복귀·배경 inert가 필수다.
- 외형상 동일한 dock가 이미 보이는 모바일 sheet 뒤에서 조작되지 않게 한다.

## 5. 흐름과 상태 계약

### 라이브러리

- 신규: 빈 상태에는 가져오기/빈 목록 만들기 두 경로. 작동할 음악이 없으므로 검색/정렬을 보여주지 않는다.
- 채워짐: 바로 검색·목록을 보여준다. 숫자는 실제 데이터, 최근 정렬은 저장된 createdAt/명시적 순서에 근거한다.
- 검색 없음: 검색어를 보여주고 ‘검색 지우기’ 제공. 기존 목록을 삭제하거나 빈 라이브러리로 오인시키지 않는다.
- 읽기 실패: 저장 데이터를 그대로 두고 다시 읽기 제공. 실패를 빈 라이브러리처럼 표시하지 않는다.
- 빈 카드: 재생 대신 ‘곡 추가’. 어떤 진입점에서도 빈 LOAD가 현재 큐를 지우지 않는다.

### 생성 / 정보 편집

- 이름 required, 설명 optional. 명확한 ‘만들기’/‘변경 저장’ 라벨.
- 생성 성공 후 새 상세로 이동하고 첫 URL 입력을 바로 사용할 수 있게 한다.
- 실제 저장 경계에서 itemCount, thumbnails, items, createdAt를 정규화한다.
- 저장 중 중복 제출 금지. 성공 전 닫지 않는다. 실패 시 입력/오류/재시도 유지.

### 저장 목록 상세 / 곡 추가

- 곡 있는 목록: 재생 액션 다음에 곡 목록. URL 폼은 ‘곡 추가’로 펼친다.
- 빈 목록: URL 폼 펼침. 전체 재생 비활성. 큐는 그대로.
- URL은 개별 YouTube 영상만 검증한다. 제목 자동 조회는 약속하지 않는다.
- 중복 영상은 조용히 버리지 않는다. 프로토타입은 같은 영상임을 알리고 ‘중복해서 추가’를 명시적으로 선택할 수 있게 했다. 실제 앱의 기존 중복 계약을 보존하되 UI와 일치시킨다.
- 편집 모드에서 위/아래 버튼으로 저장 순서 변경. 재생 중인 큐와 현재 곡의 위치는 자동 갱신하지 않는다.
- 곡 제목/커버 재생은 버튼. 행 안의 메뉴와 재생 표적이 중첩되지 않는다.

### 가져오기 / 원본 초기화

- 가져오기: URL/이름 → 미리보기 → 저장. 원본 전체 포함/제목 자동 조회를 약속하지 않는다.
- 원본 URL이 있는 목록에만 초기화 노출.
- 초기화: readonly 원본 URL → 미리보기 → 로컬 변경을 지운다는 교체 확인 1회 → 실제 교체.
- 미리보기/취소만으로 저장 데이터를 바꾸지 않는다. 별도 원본 변경이 편집본을 자동 덮어쓰지 않는다.
- 초기화 실패 시 기존 목록 보존, 미리보기/입력 유지, 재시도. 현재 큐는 독립적으로 계속 재생.

### 재생 / 큐

- 전체 재생/특정 곡 재생은 저장 목록을 큐로 복사한다. 큐의 고유 항목 key를 보존/생성하고 저장 항목과 섞지 않는다.
- 큐에는 현재곡을 포함한 전체 순서를 보여준다. 그래서 ‘다음 트랙 N’ 대신 ‘재생 대기열 N’이라고 한다.
- 현재곡은 상단 요약과 행 상태로 분명하게 표시. paused/buffering/error/playing을 모두 같은 아이콘으로 표현하지 않는다.
- 순서 변경은 포인터 드래그와 위/아래 버튼 두 경로. 현재곡은 index가 아니라 항목 identity를 따라간다.
- 큐의 항목 삭제와 순서 변경은 저장 목록을 건드리지 않는다. 큐를 저장할 때만 대상 목록을 명시적으로 선택.
- 큐 저장: 새 목록 또는 기존 목록 끝에 복사. 성공/실패는 실제 persistence 결과를 따른다.
- 제한 영상/로딩 실패는 오류 메시지와 재시도/다음 곡을 제공. 정상 재생처럼 보이는 가짜 진행률을 표시하지 않는다.
- 실제 YouTube iframe을 숨기거나 CSS로 대체해 성공을 가장하지 않는다. 프로토타입의 그래픽 슬롯은 구현 시 공식 플레이어가 들어갈 자리다.

## 6. 삭제 정책 확정

정책을 혼합해 확인창과 Undo를 매번 중첩하지 않는다.

| 동작 | 보호 방식 | 이후 상태 |
|---|---|---|
| 저장 재생목록 전체 삭제 | 이름·곡 수·복구 불가를 설명하는 확인 1회. Undo 없음 | 현재 상세라면 라이브러리로 이동. 큐 유지 |
| 저장 목록의 개별 곡 삭제 | 즉시 삭제 + Undo | 원래 목록의 원래 위치에 복구. 큐 유지 |
| 큐의 개별 곡 삭제 | 즉시 삭제 + Undo | 저장 목록 유지. 현재곡 삭제 시 유효한 다음 항목/paused 상태 |
| 큐 비우기 | 재생 중단/전체 큐 제거 확인 1회 | 저장 목록 유지 |
| 원본 초기화 | 미리보기 뒤 교체 확인 1회 | 로컬 편집본만 교체. 큐 유지 |

프로토타입 Undo 알림은 12초다. 실제 앱에서는 hover/focus 중 타이머를 멈추고 충분한 키보드 접근 시간을 확보해야 한다. 연속 삭제를 지원할 때 Undo가 다른 작업을 덮어쓰지 않도록 항목 단위 복구로 구현한다. 전체 스냅샷을 덮어써 최근 변경을 잃게 하지 않는다.

삭제 실패는 성공 알림을 내거나 대상을 화면에서 지우지 않는다. 이미 없는 목록 URL은 ‘목록을 찾을 수 없음 + 라이브러리로’로 복구하며 앱 전체 오류/새로고침 반복으로 끝내지 않는다.

## 7. 키보드와 포커스

- 모든 작업은 native button/input/select로 접근한다. 클릭 가능한 div 금지.
- Native dialog의 모달성·Tab 제한을 활용한다. 이름을 읽어주고 열릴 때 적절한 입력/설명에 포커스, 닫을 때 원래 트리거로 복귀.
- 위험 확인은 설명 제목에 초기 포커스. 기본 Enter가 무심코 삭제되도록 두지 않는다.
- 좁은 화면 큐는 Tab을 내부로 제한하고 Escape로 종료한다. 데스크톱 큐는 비모달이라 중앙 편집을 막지 않는다.
- 큐 탭은 좌우 방향키/Home/End 및 올바른 roving tabIndex 지원.
- 저장/순서 변경/오류는 live region으로 알리되 매초 재생 시간은 읽어주지 않는다.
- 전역 Space/방향키 단축키가 입력·버튼·range·dialog를 가로채지 않는다.
- 페이지 이동/없는 목록 상태에서는 제목에 포커스를 주고, 브라우저 Back/Forward도 검수한다.

## 8. 구현 순서와 완료 기준

1. 확정 데이터·저장·빈 재생 보호 결함부터 수정한다.
2. 의미 있는 버튼/공통 dialog/오류·삭제 복구 계약을 완성한다.
3. 공통 토큰과 shell/라이브러리/상세/dock/큐/모달 전체를 같은 스타일로 옮긴다.
4. 표면뿐 아니라 상태별 UI를 구현하고 `ACCEPTANCE.md`로 확인한다.
5. Chromium desktop/mobile 실제 렌더와 키보드 검수 후 디자인 인수. 실제 YouTube/실기기 검증은 별도 결과를 남긴다.

프로토타입이 실제 앱보다 빠른 모의 성공을 보여주는 부분은 production에서 반드시 실제 Promise/iframe 상태와 연결해야 한다. 로컬 테스트 통과와 외형 확인을 실제 오디오 성공으로 합치지 않는다.

## 검증 상태

소스 문법·독립 jsdom 동작 검증은 함께 제공된 결과를 참조한다. 이 환경에서는 Chromium 실행이 완료되지 않았으므로 실제 렌더·safe area·실기기·스크린리더·드래그 품질은 아직 확인 전이다. 따라서 이 문서와 4개 런타임 파일은 **구현을 위한 동결안**이며, 독립 브라우저 검수에서 확인된 결함은 수정 후 다시 인수한다.
