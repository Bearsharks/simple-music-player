## 무엇을 보여 주는가

소개 이미지는 현재 앱의 실제 렌더를 바탕으로 한다. 제품 UI를 다시 그리거나 존재하지 않는 기능을 합성하지 않았다.

- `hero.jpg` — 1600×1320. 새로 조판한 브랜드 히어로. 현재 로고 배색, 직접 작성한 SVG 파형, 실제 앱 캡처 2개를 HTML/CSS로 배치했다. 데스크톱 프레임과 모바일 프레임은 소개용 장식이다.
- `library-desktop.jpg` — 1152×720. 실제 앱 viewport 1440×900을 0.8배로 렌더한 라이브러리.
- `library-mobile.jpg` — 332×718. 실제 앱 viewport 390×844를 0.85배로 렌더한 라이브러리.
- `workspace.jpg` — 1152×720. 실제 앱 viewport 1280×800을 0.9배로 렌더한 재생목록 상세.

캡처의 재생목록 이름, 곡 제목, 아티스트명과 video ID는 모두 소개용 예시다. 실재하는 음악 카탈로그나 재생 가능성을 주장하지 않는다. 재생 버튼을 실행하지 않았으며 시간/재생 상태를 모의 성공 상태로 바꾸지 않았다. 하단은 실제 앱의 곡 선택 전 상태다. 개인 목록이나 사용자 정보를 사용하지 않았다.

현재 제품 소스 `d477332d103861a58bc9315e400908bad4893a8a`의 `dist/`를 사용했다. 외부 API 모킹과 앱 기능 변경은 없다. 캡처는 별도의 localhost origin에서 만들었으며 공개 서비스의 저장 데이터에는 쓰지 않았다.

- 글꼴은 제품의 self-hosted Geist Sans + Pretendard Variable이다. 기존 폰트 자산과 라이선스를 그대로 사용하며 자산을 중복 복사하지 않는다.
- 그림에만 설명을 숨기지 않는다. 핵심 기능, 저장 정책과 시작 방법은 README의 선택 가능한 본문으로 제공한다. 이미지에는 alt를 붙였다.
- 이미지 4개 합계 약 276KB. README가 직접 읽는 hero와 workspace는 합계 약 188KB다.

## 재현

재현은 현재 제품 브랜치 `main`에서 한다. 현재 main의 빌드를 사용한다. 위 소스 커밋은 최초 캡처 시점의 기록이다.

1. Node 24에서 `npm ci && npm run build`를 실행한다. 기본 `/simple-music-player/` base를 사용한다.
2. 저장소 루트에서 `python3 docs/readme/serve.py --port 8768`을 실행한다.
3. `http://127.0.0.1:8768/docs/readme/studio.html`을 연다.
4. ‘예시 라이브러리 준비’를 누른다. 이 동작은 localhost에서만 가능하며, `readme-` 이외 ID가 발견되면 쓰기를 거부한다. 같은 예시 namespace의 데이터만 다시 만든다.
5. 각 링크의 실제 앱이 로드되고 글꼴이 렌더된 뒤 캡처한다. viewport를 조작하지 않기 위해 wrapper 안에서 고정 크기의 iframe을 사용하며 제품 CSS는 수정하지 않는다.
   - `?view=desktop`: 상단 왼쪽 1152×720 → `library-desktop.jpg`
   - `?view=mobile`: 상단 왼쪽 332×718 → `library-mobile.jpg`
   - `?view=detail`: 상단 왼쪽 1152×720 → `workspace.jpg`
6. `hero.html`에서 실제 사진을 배치한 결과를 확인한다. `hero.html?export=1`은 800px 아래에 아트보드를 두는 캡처용 경로다. 전체 페이지 캡처에서 `(0,800,1600,1320)` 영역을 저장한다. 캡처 포인터가 아트보드에 섞이지 않게 한다.

이번 작업에서는 클라우드 브라우저의 CUA로 탐색·캡처하고, 저장한 이미지 4개를 직접 확인했다. 이미지 확장자는 실제 반환 형식인 JPEG에 맞췄다. `serve.py`와 `studio.html`은 제작·재현용이며 앱 빌드에 포함하지 않는다.
