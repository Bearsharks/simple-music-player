### 구조 판단

저장 데이터·Undo는 playlists 모델, 재생 큐는 queue 모델에 남아 있다. 공통 Dialog는 shared에 있고 feature 역의존을 만들지 않았다. 화면에 별도 저장소를 복제하지 않았다. 기존 기능 간 결합은 ARCHITECTURE.md에 명시했다.

저장 목록과 현재 큐의 독립성을 유지한다. Undo는 이후 추가/순서 변경을 보존하며, 목록 전체 삭제 또는 원본 교체 후 오래된 Undo를 거부한다. 여러 탭의 동시 수정 동기화는 보장하지 않는다.

### 디자인 판단

실제 렌더로 라이브러리 데스크톱/모바일, 상세 데스크톱, 모바일 큐/재생 오류 화면을 확인했다. 모바일 첫 커버와 첫 4개 카드 이름이 충분히 노출되며 고정 dock와 큐 접근을 유지한다. 컬러·정보 밀도·상태별 UX를 실제 앱 구현의 기준으로 채택한다.

시연 파형·곡·시간과 실제 서비스 데이터를 구분한다. 프로토타입의 모의 저장/재생 코드는 제품에 복사하지 않는다.
