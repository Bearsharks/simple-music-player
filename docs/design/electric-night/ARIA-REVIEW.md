# aria 검수 기록

검수 기준 커밋: `661da9c2cebf404c550dadc32fb267d0f3da93b7`.

### 확인한 근거

- `4c0aae8`: 생성 메타데이터, async 저장 실패/중복 제출, 빈 목록 재생 보호, 공통 dialog, 키보드 접근, 삭제 경로, 개별 곡 Undo.
- `0d4e94c`: Chromium에서 발견한 열기 click의 버블링으로 팝업이 즉시 닫히는 문제 수정. pointerdown capture로 이후 외부 조작만 처리하고 회귀 추가.
- 로컬 독립 전체 검사 62개 통과 후 팝업 재현 테스트 2개를 추가했다. 최종 CI는 64개 테스트·타입·경계·빌드·Storybook·브라우저 검사를 통과했다.
- [최종 CI](https://github.com/Bearsharks/simple-music-player/actions/runs/38865092217)
- 앱 브라우저: 1440×960, 1280×800, 390×844. UI로 목록 생성, 3곡 추가, 새로고침 영속, 모의 재생, 빈 목록 보호, 삭제 취소/성공, CSP 차단 검사.
- 독립 디자인 프로토타입: 1440×960, 390×844에서 library/detail/queue/error/empty 렌더 및 런타임 오류·가로 overflow 검사.

### 구조 판단

저장 데이터·Undo는 playlists 모델, 재생 큐는 queue 모델에 남아 있다. 공통 Dialog는 shared에 있고 feature 역의존을 만들지 않았다. 화면에 별도 저장소를 복제하지 않았다. 기존 기능 간 결합은 ARCHITECTURE.md에 명시했다.

저장 목록과 현재 큐의 독립성을 유지한다. Undo는 이후 추가/순서 변경을 보존하며, 목록 전체 삭제 또는 원본 교체 후 오래된 Undo를 거부한다. 여러 탭의 동시 수정 동기화는 보장하지 않는다.

### 디자인 판단

실제 렌더로 라이브러리 데스크톱/모바일, 상세 데스크톱, 모바일 큐/재생 오류 화면을 확인했다. 모바일 첫 커버와 첫 4개 카드 이름이 충분히 노출되며 고정 dock와 큐 접근을 유지한다. 컬러·정보 밀도·상태별 UX를 실제 앱 구현의 기준으로 채택한다.

시연 파형·곡·시간과 실제 서비스 데이터를 구분한다. 프로토타입의 모의 저장/재생 코드는 제품에 복사하지 않는다.

### 판정과 남은 검수

- 버그 청크: 위 검사 범위 통과.
- 디자인 인계: 구현 기준으로 채택.
- Electric Night 제품 구현: 진행 중, 아직 인수 완료 아님.
- 실제 YouTube 외부 재생/목록 완전 수집, 실제 휴대전화, 보조기기 접근성은 위 검사로 입증되지 않았다.
- 구현 후 같은 뷰포트의 실제 화면을 프로토타입과 비교하고 큐 열기/닫기·반응형 전환이 플레이어를 재생성하지 않는지 재검수한다.
- 운영 배포는 아직 하지 않았다.
