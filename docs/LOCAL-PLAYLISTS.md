# 로그인 없는 재생목록 전환

## 요구와 구현

2026-10-16 사용자 지시에 따라 로그인 화면·OAuth 콜백·인증 확인·서버 CRUD·토큰 발급/갱신·내 비공개 목록 가져오기를 제거했다. 기존 서버 데이터는 건드리지 않았다.

공개 재생목록 URL을 입력하면 ID로 정규화하고 브라우저에 저장한다. 이름은 사용자가 선택적으로 붙인다. 같은 ID 중복 추가는 기존 항목을 선택하며, 재접속 시 저장 목록과 선택을 복원한다. 재생은 YouTube 공식 playlist iframe의 컨트롤을 사용한다.

이 방식은 API 키/로그인이 필요 없다. 제목·썸네일·곡 전체를 Data API로 복사하는 가져오기는 제공하지 않는다. 원본의 최신 목록을 YouTube가 재생 시 로드한다. 비공개·삭제·지역/연령·임베드 제한이 있으면 재생하지 못할 수 있다.

## 데이터와 오류

- localStorage 독립 키 `simple-music-player:youtube-library:v1`
- URL 호스트/프로토콜/ID 검증, 자동 믹스와 계정 전용 특수 목록 거부
- 저장 실패 시 성공으로 표시하지 않음
- 손상·새 스키마는 자동 덮어쓰지 않고 오류 안내
- 삭제 확인과 선택 항목 삭제 시 다음 항목 선택
- 다른 탭 변경 이벤트 반영. 정확히 동시인 쓰기의 완전 직렬화는 미구현
- 도메인이 달라지면 데이터 자동 이전 불가. 사이트 데이터를 삭제하면 목록 소실

## 검증

- `npm run check`: 타입 검사, 경계 검사, 31개 테스트, 프로덕션 빌드 통과
- URL 정규화/거부, 저장 복원, 중복, 삭제·취소, 쓰기 실패, 손상 보존, 다른 탭 반영 검증
- 앱 테스트에서 fetch 없이 동작하고 iframe의 playlist ID가 맞는지 검증
- 실제 브라우저 YouTube 소리·모바일 렌더링·외부 배포는 미검증. 기존 실행 환경의 Chromium 제한 때문에 단위 테스트를 실재생 증거로 취급하지 않음

## 호스팅

기존 GitHub Pages 설정은 gh-pages 브랜치 루트, HTTPS 사용이다. 현재 Vite 기본 base는 기존 Pages 경로다. 다른 호스팅으로 이동하면 base를 맞춰 빌드하고 실제 임베드를 검증해야 한다. 호스팅/공개 권한 변경은 별도 수행한다.
