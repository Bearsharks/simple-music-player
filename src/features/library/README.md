# library: 로그인 없는 URL 재생목록

## 최소 읽기 경로

1. `model/library.ts`: URL 검증·정규화, 저장 스키마, 추가/중복/삭제 규칙
2. `ui/LocalLibrary.tsx`: 입력→저장→선택→임베드, 실패 안내, storage 이벤트
3. `ui/LocalLibrary.css`: 모바일 우선 화면

## 경계와 계약

- `app/App.tsx`가 이 기능만 마운트한다. 로그인·서버·Data API 키는 사용하지 않는다.
- 저장은 브라우저 localStorage의 버전 있는 독립 키로 한다. 다른 사이트 데이터는 지우지 않는다.
- 저장되는 것은 URL/ID/사용자 지정 이름이다. 영상 파일·곡 메타데이터를 내려받아 저장하지 않는다.
- 같은 목록은 ID로 중복 제거하고 선택한다. 삭제는 확인 후 로컬 항목에만 적용한다.
- 쓰기 성공 후 화면 상태를 확정한다. 손상/미지원 스키마는 덮어쓰지 않는다.
- 렌더링된 iframe은 YouTube의 공식 playlist embed다. 자동재생은 요청하지 않는다.
- 공개 여부나 모든 영상의 재생 가능 여부는 URL 형식만으로 검증할 수 없다. 플레이어 오류와 원본 열기 안내를 제공한다.
- URL의 목록 ID는 `extension/protocol.js`의 `validPlaylistId`와 같은 문법을 사용한다. 자동 믹스 등 목록 종류만으로 차단하지 않으며 실제 접근 가능 여부는 iframe 결과로 처리한다. 기존 2–150자 ID 문법·호스트 검증·저장 데이터 호환성을 유지한다.
- 다른 탭 변경을 수신하며 수정 직전 최신 저장 값을 읽는다. localStorage는 트랜잭션 DB가 아니므로 정확히 동시인 다중 탭 쓰기는 완전 직렬화되지 않는다.
- 도메인 변경·사이트 데이터 삭제·시크릿 모드 종료·다른 기기에 대한 지속성을 보장하지 않는다.

## 영향과 검증

`npm run impact -- library`

`npm test -- src/__test__/library.test.ts src/__test__/app.test.tsx`

제출 전 `npm run check`. 검증 대상: 정상/잘못된 URL, 중복, 재접속 복원, 선택·삭제, 저장 실패, 손상 스키마 보존, 다른 탭 변경, 무인증·무API 호출.

실제 YouTube 재생과 모바일 화면은 별도 브라우저 검증 대상이다. jsdom 테스트는 소리 재생의 증거가 아니다.
